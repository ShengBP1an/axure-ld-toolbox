# Axure LD 工具箱

把**手绘 Layout 草图**转换为 **Axure RP 可编辑的 LD 白盒矢量图形**。

完全本地运行：图片与工程文件只保存在你的机器上，无网络请求、无遥测。

```
导入草图 → 设置尺寸与比例 → 识别矢量化 → 可视化校正 → 导出分层 SVG → 导入 Axure 转换为形状
```

---

## 快速开始

```powershell
npm install
npm run dev        # 开发服务器，默认 http://localhost:5173
```

其它命令：

```powershell
npm run typecheck  # TypeScript 严格模式检查
npm run test       # 算法与逻辑单测（228 个）
npm run build      # 生产构建，产物在 dist/（base='./'，可直接双击 index.html 打开）
npm run fixture    # 生成合成测试草图到 fixtures/
npm run e2e        # 浏览器端到端验收（需先启动 dev 服务器）
```

> 依赖 Node 18+。首次运行 `npm run e2e` 前需执行 `npx playwright install chromium`。

## 它解决什么问题

关卡设计师手绘的地图草图无法直接使用。手工在 Axure 里重画一遍既慢又容易失真。

本工具自动完成从「像素」到「可编辑几何」的转换，重点保证三件事：

1. **方正房间输出为矩形**，而不是几十个节点的自由路径 —— 这样才能在 Axure 里直接拖拽调整尺寸。
2. **共享墙的相邻房间保持独立** —— 两个共用一面墙的房间必须是两个可分别选中的对象。
3. **绝不静默输出错误结果** —— 每个对象带置信度，可疑处进入问题列表并在画布高亮。

## 算法设计要点

### 为什么用平面图半边遍历，而不是轮廓追踪

这是整个工具最关键的技术决策。

手绘地图里相邻房间大量共享墙线。如果对二值图做**轮廓追踪**，共享一面墙的两个房间属于同一个连通块，会被追成「一个外轮廓 + 若干内孔」，无法得到两个独立矩形。

本工具改为在**吸附后的线段集合**上构建平面直线图（PSLG）：

1. 在所有交点处分裂线段，顶点按容差去重；
2. 每个顶点的出边按极角排序，建立半边结构；
3. 沿「进入某半边后，取其孪生边在环上的前一条」遍历，每条闭合回路即为平面图的一个面；
4. 有向面积为负的面是无界外部面，丢弃；被完全包含的面记为孔洞。

结果：`2×2 房间网格 → 4 个独立矩形`，边界坐标精确共享（实测 `x=230` / `y=190` 完全一致）。

### 骨架化的两个坑

**坑一：不能只做 Zhang–Suen。** 它保证骨架宽度为 1、连通性不变，但在缓斜线上会留下阶梯状梯形结构，其中大量像素有 3~4 个邻居。这类像素让「沿路径行走」的分支追踪出现歧义，走错就原地打转 —— 实测一条斜墙被拆成 **21 段**碎片，封闭区域完全无法闭合。

修复：`pruneRedundant` 移除冗余像素，判据是「该像素有 ≥3 个前景邻居，且其邻居集合在真实平面 8 邻接下自身连通」。注意必须用**真实平面邻接**判断邻居间连通，而非经典 Zhang–Suen 的「8 邻域环上相邻」近似 —— 后者会把对角相邻的 E 与 S 误判为两个分量（它们中间的 SE 为背景），从而拒绝删除本可安全删除的像素。修复后同一条斜线变成 **1 个闭环**。

**坑二：判定交点要用交叉数，不是邻居数。** 斜线拐角像素常有 3 个 8 邻居，按邻居数会被误判为交点。交叉数（8 邻域环上 1→0 的转换次数）对斜线拐角正确得到 2。

### 先 RDP 再拟合，而不是直接 RDP

直接 RDP 的顶点必落在原像素上，手绘抖动会残留。本工具先用 RDP 粗分拐点，再对每段做**全最小二乘**直线拟合（对竖直线不发散），最后用相邻拟合线**求交**作为顶点。得到的墙线明显更"直"。

拟合线段必须按输入点序**定向** —— TLS 求出的主方向符号是任意的，不定向会让串联顶点首尾颠倒，导致折线自我折返（实测一条 447 像素的分支曾被压成 2 像素）。

### 吸附决定了能否输出矩形

只有当上下墙严格水平、左右墙严格垂直、四角精确共点时，提取出的面才是标准矩形。三步保证：

1. **角度吸附**：绕线段中点旋转到最近的常用角（0/30/45/60/90/…），绕中点而非端点可让两端位移最小；
2. **端点聚簇**：并查集 + 网格哈希，把相近端点合并到簇心；
3. **坐标带对齐**：把彼此很近的 x（或 y）坐标统一 —— 两个相邻房间的分隔墙如果 x 相差 1px，平面图会生成一条极窄的假面。

### 拓扑守卫

节点简化必须受约束，否则细通道会被抹平。`guardedSimplify` 在每次 RDP 后校验：面积漂移、最小通道宽度、自相交、近似 Hausdorff 偏差、顶点下限。违规则按 0.55 的系数降低容差重试，最多 3 次；全部失败则**保留原始几何**并记录 `simplifyBlocked` 问题（可见、可修正），而不是静默失真。

### 几何语义择优

按「从最简到最复杂」逐级尝试，第一个通过的即采用：

| 级别 | 输出 | 判据 |
| --- | --- | --- |
| 1 | `rect` | 4 顶点、内角≈90°、边轴对齐、与 AABB 面积比 ≥0.93、面积偏差 ≤9% |
| 2 | `polygon`（旋转矩形） | 4 顶点、内角≈90°、与最小外接矩形面积比 ≥0.94 |
| 3 | `polygon`（规则） | 边长变异系数 ≤0.12、内角偏差 ≤9° |
| 4 | `polygon` | ≤12 顶点 |
| 5 | `closedPath` | 其余不规则区域 |

旋转矩形一律**展开为 polygon 顶点**，不用 `rect + transform` —— Axure 对 `transform` 的转换行为未经验证，避免坐标漂移。

### 置信度是可解释的，不是黑箱

六个因子加权：拟合残差、闭合性、**笔画支持度**（沿矢量线采样二值图，覆盖率低说明这条线"凭空产生"）、吸附位移、角度规整度、尺寸合理性。低于 0.62 进入「待确认」图层并在画布显示为虚线。

## 坐标系与比例（唯一换算源）

三个坐标空间，换算**只能**经 `src/core/geometry/transform.ts`：

| 空间 | 用途 |
| --- | --- |
| `imgPx` | 图像像素，预处理与识别的工作空间（长边下采样至 ≤2000px） |
| `unit` | **地图单位，所有 `VectorElement` 顶点与 strokeWidth 的权威存储空间** |
| `canvasPx` | 画布像素，仅在渲染与 SVG 导出时换算 |

这样「修改地图尺寸后所有坐标与线宽按同一规则更新」变成纯标量换算，天然不会出现局部对象比例不一致。非等比缩放时 `strokeWidth` 用几何平均，保证方向无关。

**「地图实际尺寸」与「输出画布像素」是两个独立概念**：只改画布像素时 unit 坐标完全不变，只有导出像素按新比例换算。

**标定与手输的冲突优先级**：两点标定成功后 `scaleSource='calibration'`；用户随后手动改尺寸则切回 `'manual'`，标定被标记 `stale`（数据保留，可一键重新应用），并明确提示 —— 不静默覆盖。

## 导入 Axure RP

1. 在导出步骤点击「保存 SVG」。
2. Axure 中新建页面，建议先把页面尺寸设为与工具中「Axure 输出画布」一致的像素值。
3. `File → Import…`，或直接把 `.svg` 拖入画布。
4. 选中导入的 SVG 对象，右键 → `Transform Image → Convert SVG to Shapes`（转换 SVG 为形状）。
5. 在 `Outline / 概要` 面板确认能看到按图层分组的对象树，并能单独选中每个房间与墙线。

工具内「导出」步骤右栏有完整图文步骤，也可另存为 Markdown 说明文件。

### SVG 兼容层保证

- `viewBox` 与 `width/height` 严格等于设置的画布像素；
- 只用 `line` / `polyline` / `rect` / `polygon` / 仅含 `M L Z` 的简单 `path`；
- 每个逻辑对象有稳定、唯一、可读的 id（如 `region-rect-0003`）；
- 按 `边界 / 墙线 / 封闭区域 / 待确认` 建立 4 个顶层 `<g>`；
- 样式全部内联，不依赖外部 CSS；
- **不使用**滤镜、蒙版、裁剪路径、脚本、外部资源、`transform`；
- 不合并为位图或 `fill-rule="evenodd"` 复合路径；孔洞导出为独立对象 + `data-hole-of`；
- `<metadata>` 记录地图尺寸、单位、`pixelsPerUnit`、工具与算法版本。

## ⚠️ 能力边界（请务必阅读）

- 交付物是 **Axure 兼容的可编辑 SVG**，**不直接生成或修改 `.rp` 文件**。
- **不通过** Axure MCP 或任何未公开接口写入 Axure 工程。
- 首版**不识别手写文字**（无 OCR），**不识别**出生点、掩体、高低差、资源点、玩家动线等 LD 玩法语义。
- 不做多人协作、云端项目管理与版本管理。

### 需在你的 Axure 版本上验证的项

以下行为**尚未**在真实 Axure RP 上验证，不应假设无损。工具内「需验证的兼容项」面板对每项都给出了最小验证实验。

| 项 | 风险 |
| --- | --- |
| `Convert SVG to shapes` 的可用性与菜单位置 | 随版本变化；旧版本可能没有此功能，导入后只能作为图片 |
| 嵌套 `<g>` 分组层级是否保留 | 可能被拍平（对象本身仍应可分别选择） |
| `stroke-dasharray`（待确认图层虚线） | 可能被转为实线，或拆成大量小线段导致对象数暴增 |
| `fill-opacity` 半透明填充 | 可能被丢弃变为不透明，遮挡底层墙线 |
| `data-*` 自定义属性 | 几乎确定会在转换为形状时丢失 |
| `<metadata>` 是否影响显示 | 按规范不渲染；极少数解析器可能报错 |
| 坐标精度与位置漂移 | Axure 可能对坐标取整，产生亚像素位移 |
| 大量对象的性能 | 超过 2000 对象时编辑与生成原型会明显变慢 |

## 项目结构

```
src/
├── types/                    # 严格类型定义（判别联合、错误码、参数）
├── core/                     # 纯算法，不依赖 DOM，可独立测试与替换
│   ├── geometry/             # 向量、RDP、直线拟合、多边形、求交、transform（唯一换算源）
│   ├── preprocess/           # IPreprocessor 接口 + 纯 TS 实现
│   ├── recognize/            # 细化、骨架图、线段拟合、吸附、桥接、平面面提取、分类、置信度、拓扑守卫
│   ├── simplify/             # GeometrySimplifier：唯一的 imgPx → unit 换算点
│   ├── export/               # SvgExporter、预检、Axure 说明与需验证清单
│   ├── project/              # 设置逻辑（锁比 / 标定冲突）、工程序列化
│   └── pipeline/             # 参数预设、runPipeline
├── workers/                  # 管线 Worker（协议 + 实现）
├── store/                    # zustand：项目状态、编辑器状态、EditorCommand 实现
├── editor/                   # 画布：渲染器、视口、空间索引、命中测试、吸附引擎
├── components/               # UI：外壳、步骤条、各步骤面板、检查器、问题列表
└── lib/                      # ID、精度、文件读写、日志

tests/                        # 228 个单测，含合成样本生成器
scripts/                      # 合成草图生成、浏览器端到端验收
```

### 模块契约

```
ImagePreprocessor → StructureRecognizer → GeometrySimplifier → VectorEditorModel → SvgExporter
```

错误统一为带 `code` 的 `PipelineError`，绝不抛裸字符串。可恢复错误（`NO_STRUCTURE_FOUND` / `TOO_NOISY` / `TOO_MANY_ELEMENTS` / `LOW_CONTRAST`）在 UI 展示原因并给出可操作建议。

### 为什么不用 OpenCV.js

`opencv.js` 是 8–10MB 的 WASM 包，安装易失败、首屏加载重，且其 API 无法覆盖本工具最关键的「骨架图 → 平面面提取 → 几何语义分类」环节。所需的积分图自适应二值化、形态学、Zhang–Suen 细化、Moore 边界追踪、RDP、最小外接矩形均以数百行 TypeScript 精确实现，便于逐参数单测与调优。

预处理层定义了 `IPreprocessor` 接口，未来若需 OpenCV.js，只需新增实现该接口的 `PreprocessorCv`，识别层与导出层无需改动。

## 性能预算

| 指标 | 目标 | 实测 |
| --- | --- | --- |
| 输入上限 | ≤25MB，≤8000×8000 | 超限给出明确提示与压缩建议 |
| 识别耗时 | 2000px 长边 ≤3s | 1000×700 综合场景 **0.2s** |
| 对象规模 | 建议 ≤2000 | 超出时预检警告 |
| 撤销栈 | 100 步 | 超出丢弃最早项 |
| 产物体积 | — | 主包 357KB（gzip 120KB）+ Worker 69KB |

识别在 Web Worker 中执行，主线程不阻塞，支持取消与分阶段进度上报。热点优化：积分图自适应二值化 O(N)、细化双缓冲 + 变更标记提前收敛、命中测试与吸附走均匀网格索引、渲染做视锥剔除。
